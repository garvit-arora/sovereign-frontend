The problem

Industrial optimization should not depend on a rented black box.

Refineries, power systems, logistics networks and production planners all rely on mathematical optimization — but most teams either rent expensive cloud solvers or depend on foreign solver licenses they cannot inspect or adapt.

Sovereign answers SIH Problem Statement 26119 with a native C++ solver core, a web workspace for submitting jobs, and a connector that runs computation on hardware the organization already owns. The coordinator routes work; the solve happens locally.

Architecture

From model upload to verified result

  1. 01

    Sign in and submit a job

    Upload a JSON or MPS model on the website. Choose algorithms, a time limit, and whether to prefer CPU, CUDA, or automatic device selection. Pick a specific machine or let the queue assign the first compatible worker.

  2. 02

    Coordinator queues and routes

    The hosted backend stores the job, matches it to an online worker with the right capabilities, and tracks state from queued through running to completed. No GPU is required on the server — it only mediates.

  3. 03

    Your machine solves locally

    The npm connector polls over outbound HTTPS, claims the job, and runs the Sovereign C++ engine on your laptop, workstation, or CUDA server. No inbound port needs to be opened on your network.

  4. 04

    Results return with verification

    The website shows the objective, primal variables, runtime, solver status, independent verification outcome, and — when CUDA was used — the actual GPU operation count.

npm connector

One install. One command. Your hardware.

sovereign-compute bundles the Windows solver binary — no git clone, no manual build step. Run sovereign connect, approve the short code in your browser, and choose how long the machine stays linked (1 to 72 hours).

  1. Install the package globally with npm.
  2. Run connect against the Sovereign coordinator URL.
  3. Enter the 6-digit code on the website and pick a duration.
  4. Submit jobs — they execute on that machine until expiry or disconnect.

Solver core

Algorithms implemented in Sovereign's own C++ engine

Established solvers are used as benchmark comparators, not as the production engine. The codebase is built for inspectability, presolve, sparse structures, and honest reporting.

Class Approach Notes
Linear programming (LP) Revised simplex + primal-dual interior-point Mehrotra-style predictor–corrector; presolve before solve
Mixed-integer LP (MILP) Branch-and-bound / branch-and-cut LP relaxations, cuts, heuristics, branching strategies
Convex QP Continuous quadratic optimization Numerical and solution checks on returned points
GPU path CUDA sparse matrix operations Accelerates applicable steps; other work stays on CPU

MIQP, NLP and MINLP are on the roadmap per the problem statement — not claimed as current capabilities.

Why Sovereign

Built for teams that need to see what the solver actually did

Solver independence

Core LP, MILP and QP logic lives in Sovereign code. You can study algorithm behavior and compare against HiGHS or other tools without inheriting their license terms for production use.

Bring-your-own compute

Route jobs to a laptop, plant server, or CUDA workstation. Avoid paying for a cloud GPU on every solve when the hardware is already in the building.

Honest GPU reporting

Results include whether CUDA kernels ran and how many GPU operations occurred. Selecting "GPU" is never presented as proof of speedup by itself.

Verification alongside status

The platform returns independent solution checks so users can tell a returned answer apart from a validated one — important for planning and operations teams.

Measured, not marketed

What the prototype has shown so far

0 GPU operations in a verified LP end-to-end test
0 Median CPU time at 10k variables (synthetic transport)
0 Median CUDA time at same size — execution, not speedup

Benchmarks establish that GPU kernels execute and solutions verify. Whole-solver CUDA speedup is evaluated case by case — transfer cost matters.
